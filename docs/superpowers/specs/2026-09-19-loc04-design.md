# LOC draft-04 support alongside LOC-01

Date: 2026-09-19
Branch: feature/loc04
Source drafts: `docs/draft-ietf-moq-loc-04.txt`, draft-ietf-moq-loc-01

## Goal

Parse and emit the LOC property set defined by draft-ietf-moq-loc-04 while
continuing to interoperate with peers that use draft-ietf-moq-loc-01. Playback
behaviour must not regress for LOC-01 tracks, LOCMAF tracks, or CMAF tracks.

## Out of scope

- Secure Objects integration (draft-04 section 3): private properties, key
  identification, AAD construction, and payload encryption. The parser keeps a
  seam for merging a decrypted private property block later.
- Track-scoped properties delivered by the transport. draft-04 marks Timescale,
  Video Config, and Audio Config as Track or Object scope, but the transport
  package does not surface track-scoped properties today. The parser accepts a
  caller-supplied track context so this can be wired later without an API change.
- A catalog field that names the LOC version. Detection is done from the bytes.

## Wire delta between the two drafts

| Property | LOC-01 | LOC-04 |
|---|---|---|
| Timestamp | 0x02, integer, always microseconds since Unix epoch | 0x10, integer, unit set by Timescale, microseconds when absent |
| Timescale | none | 0x08, integer, units per second |
| Video Frame Marking | 0x04, integer carrying RFC 9626 bits | 0x09, length-prefixed RFC 9626 bytes, 1 to 4 bytes |
| Audio Level | 0x06, integer | 0x0C, integer |
| Video Config | 0x0D, bytes | 0x0D, bytes |
| Audio Config | none | 0x0F, bytes |

The two ID sets are disjoint except for Video Config. Integer properties have
even IDs and byte properties have odd IDs in both drafts, and the transport
package already enforces that parity at the wire layer.

## Decisions

1. One `LocHeaders` model covers both drafts. Consumers keep reading
   `captureTimestamp` in microseconds.
2. The parser accepts both ID sets in one pass and reports the dialect it saw.
3. The encoder takes an explicit `locVersion`, default 4.
4. Mixed input never throws. Any 04-only ID makes the block version 4, and the
   01 IDs 0x02, 0x04, 0x06 in that block are kept in `unknown`.
5. Encoding a header that version 1 cannot represent throws.

## Package `@moqt/loc`

### Types

```ts
export type LocVersion = 1 | 4;

export const Loc01PropertyId = {
  CAPTURE_TIMESTAMP: 0x02,
  VIDEO_FRAME_MARKING: 0x04,
  AUDIO_LEVEL: 0x06,
  VIDEO_CONFIG: 0x0d,
} as const;

export const Loc04PropertyId = {
  TIMESCALE: 0x08,
  VIDEO_FRAME_MARKING: 0x09,
  AUDIO_LEVEL: 0x0c,
  VIDEO_CONFIG: 0x0d,
  AUDIO_CONFIG: 0x0f,
  TIMESTAMP: 0x10,
} as const;

/** @deprecated Use Loc01PropertyId. Kept so existing imports compile. */
export const LocExtensionId = Loc01PropertyId;
```

`VideoFrameMarking` gains `tl0PicIdx?: number`, present only when the 04 long
form carries it. All existing fields keep their meaning.

`LocHeaders` gains these fields. Existing fields are unchanged.

| Field | Type | Meaning |
|---|---|---|
| `version` | `LocVersion \| undefined` | Dialect detected on parse. Undefined when only shared IDs (Video Config) or nothing version-specific was present. Ignored on encode. |
| `timestamp` | `bigint \| undefined` | Raw Timestamp value as carried on the wire, in Timescale units. Under version 1 this equals `captureTimestamp`. |
| `timescale` | `bigint \| undefined` | Timescale property. Never set by the version 1 path. |
| `audioConfig` | `Uint8Array \| undefined` | Audio Config bytes. |
| `timestampIsWallClock` | `boolean \| undefined` | True when a timestamp was present and no Timescale was seen (wire or track context). False when Timescale was present. Undefined when no timestamp. |

`captureTimestamp` is always microseconds. On parse it is derived as follows,
in bigint arithmetic, truncating toward zero:

- No Timescale: `captureTimestamp = timestamp`.
- Timescale present and non-zero: `captureTimestamp = timestamp * 1_000_000n / timescale`.
- Timescale present and zero: the block is malformed. The parser throws
  `LocHeaderError` so the player's Malformed Track path fires.

### Parse

```ts
export interface LocHeaderOptions {
  readonly deltaEncoded?: boolean;         // unchanged
  readonly wireProfile?: PropertyWireProfile; // unchanged
  readonly locVersion?: LocVersion;         // encode only, default 4
  readonly track?: LocTrackContext;         // parse only, optional defaults
}

export interface LocTrackContext {
  readonly timescale?: bigint;
  readonly videoConfig?: Uint8Array;
  readonly audioConfig?: Uint8Array;
}
```

`parseLocHeaders(bytes, options)` decodes the property block with the existing
Layer A codec, then `resolveLocHeaders(entries, track?)` interprets it:

1. Walk entries once. Known 01 IDs and known 04 IDs each set a candidate field.
   Unknown IDs go to `unknown` as today.
2. If any 04-only ID was seen, `version = 4`. Candidate values from 01 IDs are
   moved to `unknown` under their original ID.
3. Else if any 01-only ID was seen, `version = 1`.
4. Else `version` is undefined.
5. Object-level Timescale, Video Config, and Audio Config override the track
   context. Track context fills only what the object omitted.
6. Derive `captureTimestamp` and `timestampIsWallClock` per the rules above.

Duplicate known IDs resolve last-wins, as today.

### Frame marking codecs

`video.ts` keeps `parseVideoFrameMarking(bigint)` and
`encodeVideoFrameMarking(marking): bigint` for version 1.

It adds `parseVideoFrameMarkingBytes(bytes)` and
`encodeVideoFrameMarkingBytes(marking): Uint8Array` for version 4, following
RFC 9626 section 3.1:

- 1 byte: `S E I D B TID`.
- 3 bytes: the first byte, then `LID` (8 bits), then `TL0PICIDX` (8 bits).
- 2 bytes: first byte then `LID`, accepted on parse for leniency, never emitted.
- 4 bytes: accepted on parse, the fourth byte is ignored, never emitted.
- 0 bytes or more than 4: throw `LocHeaderError`.

Encode emits 1 byte when `layerId` is undefined, otherwise 3 bytes with
`tl0PicIdx` defaulting to 0.

### Encode

`encodeLocHeaders(headers, options)` projects to a property map for the
selected version, then encodes with Layer A as today.

Version 4 projection:

- `timestamp` if set, else `captureTimestamp`, into 0x10.
- `timescale` into 0x08 only when `timestamp` was the source. If the caller set
  `captureTimestamp` only, no Timescale is emitted, which the draft defines as
  microseconds.
- `videoFrameMarking` into 0x09 as bytes.
- `audioLevel` into 0x0C.
- `videoConfig` into 0x0D, `audioConfig` into 0x0F.
- `unknown` entries pass through.

Version 1 projection:

- `captureTimestamp` into 0x02. If only `timestamp` and `timescale` are set,
  derive microseconds first.
- `videoFrameMarking` into 0x04 as integer. If `tl0PicIdx` is set, throw.
- `audioLevel` into 0x06, `videoConfig` into 0x0D.
- `timescale` when not derivable away, or `audioConfig`: throw `LocEncodeError`
  naming the field. Silent dropping would corrupt timing or decoder setup.
- `unknown` entries pass through.

`LocHeaderError` and `LocEncodeError` are exported from the package.

### Chunk init helpers

`toVideoChunkInit` and `toAudioChunkInit` are unchanged. They already read
`captureTimestamp`, which stays microseconds.

## Package `@moqt/playback`

The pipeline's contract stays `headers.captureTimestamp` in microseconds. Two
places compare against a wall clock and must be gated on
`headers.timestampIsWallClock !== false`:

- `SyncController` latency measurement (`wallClock.now() - captureTimestampUs`).
  Media-time timestamps produce a meaningless latency, so the method returns
  undefined and callers already handling absence keep working.
- Adaptive tolerance `onFrameArrived` in `pipeline.ts`. Skip the feed when the
  timestamp is media time.

Relative scheduling, catch-up, and gap detection use differences between
timestamps and are correct in either domain.

The audio pipeline's `configure(bytes)` gains a per-object path: when a LOC
object carries `audioConfig` and the decoder is not yet configured with those
bytes, reconfigure with them. This mirrors the existing Video Config handling.

## Package `@moqt/browser`

`WebCodecsAudioDecoder.configure` currently ignores config bytes and uses ADTS
mode for AAC. With Audio Config present, pass the bytes as
`AudioDecoderConfig.description`. For AAC that switches the decoder to raw
frame mode, which is what a publisher sending Audio Config expects. With no
bytes the ADTS behaviour is unchanged.

## Package `@moqt/player`

- `subscription-manager.ts`: no logic change. The parse options object grows a
  `track` field that is left undefined until the transport surfaces
  track-scoped properties.
- `player.ts` LOCMAF synthesis: keep setting `captureTimestamp` from
  `ticksToMicros`. Also set `timestampIsWallClock: false`, since CMAF
  presentation time is media time. This makes the LOCMAF path honest about the
  domain and switches off wall-clock latency for it.
- `config.ts` `extensionParser` doc comment updated to name both drafts.

## Testing

`packages/loc`:

- Round trip every field under version 4 and under version 1 for each wire
  profile.
- Detection: 01-only, 04-only, shared-only, empty, mixed.
- Timescale derivation: 90000 and 48000 exact cases, truncation case, values
  above 2^53, timescale zero throws.
- Version 1 encode rejections for timescale and audioConfig, and for tl0PicIdx.
- Frame marking bytes: 1, 2, 3, 4 byte inputs and out-of-range lengths.
- Track context fills omitted fields and never overrides object values.

`packages/playback`:

- A stream with timestamp plus timescale schedules identically to its
  microsecond equivalent.
- Latency and adaptive tolerance are skipped when `timestampIsWallClock` is false.
- Audio Config triggers a decoder reconfigure once, not per object.

`packages/player`:

- LOCMAF synthesized headers carry `timestampIsWallClock: false`.
- Audio Config from a LOC object reaches the audio pipeline configure call.

Conformance corpus regenerated and the diff suite green.

## Compatibility notes

- Existing callers that only set `captureTimestamp` keep compiling and, with
  the version 4 default, emit a 0x10 Timestamp in microseconds. Our player
  auto-detects, so in-repo round trips are unaffected. Anyone publishing to a
  LOC-01-only peer must set `locVersion: 1`.
- `LocExtensionId` remains exported as an alias to avoid a breaking change in
  this release. It can be removed in a later major version.
